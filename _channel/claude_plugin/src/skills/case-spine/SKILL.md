# Story spine — stage 4

Read `references/rules.md`, `references/drive-workspace.md`, `references/data-contract.md` and `references/gates.md` before working on a case. These references are bundled with this skill. Read `references/story-format.md`; use `references/pilot-darkhorse.md` only for that pilot.

Read the current brief, decisions, evidence and selects. Preserve approved scope. Create/update the Story Spine Sheet with Beats, Knowledge States and Act Timing tabs.

For each beat, specify: question; audience learns; actual new development; precise evidence/select links; sound and picture separately; estimated duration; reveal order; human context; open checks. Do not confuse estimated beat duration with measured source length. Note candidate knowledge-ledger slots where the case earns them. Give silence a purpose rather than a fabricated revelation.

Build the selected case pattern with flexible act counts. Label reveal order separately from event chronology. Track cold-open returns and what they add. A knowledge state appears only if a meaningful difference is supported, with dated police knowledge and what has already been shown to the audience. Do not announce a closed case when the columns converge.

Review the whole spine: central question advances; each return adds meaning; context is timely; victim is present; no speculative guilt cues; repetitions are removed; acts sum to the proposed total. Flag weak beats with a concrete remedy (source needed, merge, trim, reorder, replace) instead of padding.

Save and read back all tabs, record awaiting_review with exact revision, and return the outline's creative logic, total estimated runtime and the few decisions that materially affect it. Next is the opening test; do not claim an outline is an assembled film.
