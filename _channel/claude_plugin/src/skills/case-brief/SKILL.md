# Case brief — stage 3

Read `references/rules.md`, `references/drive-workspace.md`, `references/data-contract.md` and `references/gates.md` before working on a case. These references are bundled with this skill. Read `references/story-format.md`. Read `references/pilot-darkhorse.md` only for DARKHORSE.

Read current Case Record, source coverage, chronology/conflicts, Evidence, People/Locations, report and Selects. If verification is incomplete, write only a clearly labeled development draft with outstanding checks; do not treat it as an approved production brief.

Write a concise 1–2 page equivalent brief:
- Logline and investigative question.
- Chosen story pattern and why the evidence supports it; do not force a manhunt or exhibit count.
- Primary cold-open proposal plus an alternate only if useful: exact selects/citations, what the audience learns, context required, missing checks. Around 90 seconds for DARKHORSE, measured later.
- Victim's early introduction and how human context returns throughout the film.
- Principals, roles at the time and relevant relationships, with evidence links.
- Proposed act functions and duration allocation within the 15–30 minute range.
- Strongest authentic moments, each with a unique purpose.
- Useful graphics/knowledge-panel states and selective recreation ideas, each with purpose, evidence, available references and labeling. No minimum count, person-based lens assignments or invented HUD data.
- Key geography/privacy treatment, source/use limits and consequential open questions.

Save/update the Brief Doc, read back and record its exact revision as awaiting_review. Give a short creative recommendation and invite review. If the user already approved an unchanged revision, record it once and continue within scope. Changes invalidate only affected approvals. After approval, record the chosen structure, runtime and visual treatment; next is story spine, now supported by `case-spine`.
