# Pre-script — stage 5b

Read `references/rules.md`, `references/drive-workspace.md`, `references/data-contract.md` and `references/gates.md` before working on a case. These references are bundled with this skill. Read `references/story-format.md` (especially the storytelling devices) and for DARKHORSE `references/pilot-darkhorse.md`.

Read the approved spine, the opening-test outcome, selects, evidence and existing approvals. If the opening test has not passed, proceed only with that dependency stated; do not imply it passed. Build on the spine; do not restructure an approved spine silently.

1. Create/update the Pre-Script Doc (`C###_08B_PRE_SCRIPT`) as one readable document, beat by beat in reveal order, that a person can read start to finish and understand the whole story before final narration exists. Use the beat-block template in the data contract: Visuals, Voice over, Sound bites, Function, Checks.
2. Visuals: name the asset, select or visual ID where one exists; describe plainly where it does not yet. This is the story document, not the shot list: no camera treatment, transitions or durations beyond what reading the beat needs.
3. Voice over: write narration intent and, where already clear, the draft line, using the device set. Name the device when it is not obvious. Vary devices across transitions; mark beats that run on authentic sound with `(no VO — authentic sound)`.
4. Sound bites: verbatim from checked transcripts only, with speaker, asset/EVD and in/out. A transcript-only excerpt stays flagged unreviewed. Never write or paraphrase participant speech as a quote.
5. Mark every knowledge-ledger moment here as its own block (known / supported / unresolved, each with EVD links), at slots the case earns. Flag any line whose support is open as a check, not as copy; label the Doc DEVELOPMENT DRAFT while checks remain.
6. Update Beats where the pre-script changed a beat's function, order, evidence links, devices or ledger_moment. Preserve beat IDs; append or retire, never renumber.

Self-review before saving: the episode reads clearly end to end; every beat earns its place; each claim traces to evidence or is marked open; device use is varied rather than one device repeated; the victim is present early, throughout and at the end.

Save and read back, record awaiting_review with the exact revision and set the case stage to Pre-Scripted only on approval. Return the Doc link, the story's shape in a few lines, ledger placements, open checks and the decisions that most affect the script. Approval releases stage 6a (`case-script`), which expands this document rather than restarting from the spine.
